ThreatLens AI Test Guide

Backend checks

From backend with requirements installed:

python -m compileall -q app tests
python -m pytest -q

These commands compile and run the backend test suite. PE/YARA-specific behavior requires the declared pefile and yara-python dependencies.

Manual startup

  1. Copy backend/.env.example to backend/.env.
  2. Set a unique high-entropy JWT_SECRET and bootstrap admin credentials.
  3. From backend, run alembic upgrade head, then python -m uvicorn app.main:app --host 127.0.0.1 --port 8000.
  4. From frontend, run npm install and npm run dev.
  5. Sign in as admin, create/approve users as required, and confirm role restrictions are enforced by the API.

Static upload workflow

  1. Use a harmless supported PE executable fixture and submit it through Live Scan.
  2. Confirm hash, file metadata, parsed PE fields, strings, URLs/IPs and local YARA matches as available.
  3. For .exe samples with model readiness, inspect model label, feature coverage, missing-input list, unseen-category count and partial-estimate warning.
  4. Use a harmless non-PE or unsupported extension to confirm the scan can still return static/YARA analysis while model inference is skipped when unsupported.
  5. Confirm model unavailability or parser errors are shown separately from a benign label.

Never execute uploaded samples. A model prediction that imputes runtime telemetry is a partial estimate, not a live behavioral result or a calibrated probability.

Model readiness and evaluation

  1. Confirm the configured Random Forest and paired schema exist under backend/ml/artifacts/candidates/user_supplied_random_forest_2026-10-16/.
  2. Use the pinned scikit-learn 1.9.1 environment and request /api/model/readiness.
  3. Request /api/model/evaluation; its metrics/report/feature-importance are saved training artifacts, not live accuracy.
  4. For representative model validation, use a labeled source/family/time-separated holdout and review false positives and false negatives.

Frontend and authorization workflows

Build the frontend with npm run build, then sign in under each supported role, inspect permitted pages, and try denied API actions. Check scan history/details, reporting, analytics, incidents, research notes and responsive layouts.

Use docs/ROLE_FEATURE_ACCEPTANCE_MATRIX.md and the API reference for the role matrix and endpoint expectations. For full backend regression coverage, run python -m pytest -q from backend.

Common errors

  • 401: sign in again; token may be missing or expired.
  • 403: the current role lacks permission.
  • Connection refused: check Uvicorn port and VITE_API_URL.
  • CORS: add the exact frontend origin to CORS_ORIGINS and restart the API.
  • Model unavailable: check artifact/schema paths, feature order and scikit-learn version.
